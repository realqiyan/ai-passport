# 语音设备耗电排查与省电改动

首次记录：2026-10-06。更新：2026-10-07。目标：降低电池待机耗电，并缩短按键后的恢复等待。

最新阶段见[2026-10-07 二次优化](#2026-10-07-二次优化)。第二版 `idle-v2` 已于 2026-10-07 在目标 Mac 重建并刷入，设备上报 `power_profile=idle-v2`；实机功耗和恢复时间仍未测量。下方第一轮说明对应 `cafc34c`，保留当时的结论和验证边界。

2026-10-06 首次观察：电量从 99% 降到 0%，设备自动关机，用时不足一天。用户确认期间使用 Wi-Fi，Mac 桥接一直运行。当时未确认具体小时数、熄屏和麦克风状态；电池容量也未实测。

用户已确认的取舍：允许空闲后断开 Wi-Fi，按键后等待重连，以续航为优先。本轮已实现并构建对应改动。2026-10-06 在目标 Mac 重建并刷入设备，设备状态确认新固件在运行；实际电流和续航仍未测量。

## 结论与证据边界

旧版设备只降频和熄背光，没有 CPU 睡眠。Wi-Fi 连接、按键扫描和后台轮询持续运行。少量说话不能代表低功耗待机。这些代码事实足以说明续航存在优化空间，尚不能确定各部件的耗电占比。

还需区分持续开麦。上键开启麦克风后，即使没有说话，设备仍以 16 kHz 采集并发送 PCM。CPU 持有 160 MHz 锁，屏幕保持亮起。确认键临时输入也需要再次确认结束。原有操作规则没有静音自动结束；本轮保留此规则。

设备没有软件“电量为 0 就关机”的逻辑。用户观察的自动关机可能来自欠压或硬件保护，也可能存在其他原因。没有电压、复位原因或电流记录，不能认定为电池损坏或软件关机。

证据来自维护的[主程序](firmware/main/main.c)、[音频与传输任务](firmware/main/voice_runtime.c)、[Mac 桥接](bridge/voice_bridge/cli.py)、[构建配置生成器](../apply_voice.py)。官方 BSP 基线为 `33d3d1d93a1125b356b47b6d83a7a60121be801e`，ESP-IDF 为 5.5.3。设备实际镜像未在本轮读取；此前刷机身份见[审查记录](REVIEW.md)。

## 各耗电路径

| 路径 | 旧版代码事实 | 影响与结论 |
| --- | --- | --- |
| CPU | `light_sleep_enable=false`；只启用 40–160 MHz 动态降频 | 待机仍需供电。实际频率还受 Wi-Fi、外设和任务锁影响 |
| 系统 tick | 基线为 1000 Hz，Tickless Idle 默认关闭 | 固定周期唤醒。降频不能替代睡眠 |
| 按键 | button 4.2.0 默认每 5 ms 扫描 ADC；当前驱动没有启用按键组件的省电模式 | 约 200 次扫描/秒。若只打开 Tickless Idle，5 ms 定时器仍短于本配置的默认 8 ms 入睡门槛 |
| Wi-Fi | 选择 Wi-Fi 后保持关联；没有空闲停无线流程 | RF 定期接收路由器信标及网络流量。Mac 退出也不会自动停止 Wi-Fi |
| Wi-Fi 节能 | 应用未调用 `esp_wifi_set_ps`；IDF 默认是 `WIFI_PS_MIN_MODEM` | 不能说旧版完全没有 Wi-Fi 节能。实际收益受路由器 DTIM 和网络流量影响 |
| 传输任务 | 关麦后仍每 20 ms 检查 USB、TCP、UDP、队列及状态 | 约 50 次循环/秒，增加 CPU 唤醒 |
| 心跳与状态 | Mac 每秒发送心跳；设备对命令回包，另每 500 ms 主动发状态 | 空闲时约每秒 1 次命令、3 次状态，不含 TCP ACK。确切耗电需测量 |
| 显示 | 关麦后 30 秒熄背光并停 LVGL 定时器；没有让 ST7789 进入 Sleep In | 屏幕黑了，面板控制器仍可能耗电。开麦时不会熄屏 |
| 音频 | 首次开麦才初始化音频；正常关麦后强制休眠 ES8311、停 I2S、释放 CPU 锁 | 没有证据证明关麦后仍持续录音。首次录音前的芯片上电状态未被应用明确设置 |
| 外置功放 | BSP 的 `BSP_I2S_PA_CTRL=-1`，没有 MCU 可控使能脚 | 软件不能切断其供电。残余静态耗电属于待测硬件限制 |
| 电量计 | CW2017 每 30 秒读取一次；使用厂商 520 mAh 电芯 profile | 未发现高频查询。SOC 是估计值，profile 正确不能代替容量和电压验证 |
| USB | 即使使用电池 Wi-Fi，USB Serial/JTAG 驱动仍存在 | 有残余耗电。不能直接禁用，否则会影响 USB 输入、配网和后续连接 |
| 蓝牙 | 应用不初始化 BLE，但旧默认配置仍启用 BT/NimBLE | 没有证据证明旧版在广播；编译选项不等于射频已开启 |
| 断线与弱信号 | 断开 AP 后立即重试连接；没有退避 | 路由器不可达或频繁掉线时可能增加扫描、发射和重试。此次 AP 连接是否稳定未知 |

官方资料说明：自动浅睡眠需要 Tickless Idle；定时器与电源锁会限制入睡。[ESP-IDF 5.5.3 电源管理](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/system/power_management.html)。

`WIFI_PS_MIN_MODEM` 是默认值。最大节能会增加接收延迟，并可能丢失广播，影响现有自动发现。本轮保留最小 Modem-sleep，主要通过空闲停无线节电。[ESP-IDF 5.5.3 Wi-Fi 节能](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-guides/wifi.html#esp32-c3-wi-fi-power-saving-mode)。

硬件残余耗电依据：[固定官方基线的音频、电量计与引脚说明](https://github.com/FoloToy/ai-passport/blob/33d3d1d93a1125b356b47b6d83a7a60121be801e/docs/hardware-design/AI_HARDWARE_DEVELOPMENT_GUIDE.md)。

## 本轮实现

| 状态 | 新行为 |
| --- | --- |
| 正在录音 | 保留 160 MHz 锁、PCM 传输、亮屏及原有确认结束规则 |
| 关麦后 30 秒无操作 | 停 LVGL 定时器，熄背光，让面板关闭显示并进入 Sleep In |
| 关麦后 60 秒无操作，处于 Wi-Fi 模式 | 关闭客户端、TCP/UDP 监听，调用 `esp_wifi_stop()`。模式和配网信息保留 |
| 无任务和电源锁需要运行 | IDF 自动浅睡眠，按下一次定时器期限唤醒；没有进入 Deep-sleep |
| 停无线后的首次按键 | 唤醒屏幕并恢复 Wi-Fi；本次按键只用于唤醒。桥接 ready 后再次按确认开始输入 |
| USB 主机连接 | `CONFIG_USJ_NO_AUTO_LS_ON_CONNECTION=y` 阻止自动浅睡眠，保留 USB 链路 |
| 按键初始化失败 | 不自动熄屏或停无线，避免无法唤醒 |
| Mac 遇到 Wi-Fi 断线 | 清理音频与默认输入后自动重试。等待为 2、4、6、8、10 秒，此后每次等待 10 秒 |

按键扫描改为每 20 ms，一秒约 50 次。它允许更长的入睡窗口，但仍有周期唤醒。短按、长按和低电量时的按键响应必须实机验证。

启动时先初始化并休眠 ES8311，明确设置首次录音前的低功耗状态。关麦后的既有寄存器校验和 I2S 停止流程保留。显式设置 `WIFI_PS_MIN_MODEM`，关闭未使用的 BT/NimBLE 构建选项。

状态包减少重复发送。Mac 的每秒心跳及 3 秒失联保护保留，避免把省电改动变成较长的持续录音失联窗口。自动发现启动的桥接先重试已知地址，每五次失败再尝试发现，支持 DHCP 地址变化。手动指定地址时继续使用该地址。令牌拒绝、配置和音频错误不会作为 Wi-Fi 休眠反复重试。

状态新增 `power_profile=idle-v1`、`battery_pct`、`battery_mv`、`uptime_s`、`screen_off`、`codec_asleep` 和 `wifi_idle`。Mac 终端显示电量、电压及屏幕、音频休眠状态。`-1` 表示电量或电压不可用。

这些状态不等于电流测量，也不证明 CPU 实际睡眠占比。停无线时没有网络采样；唤醒后可读取新的电量和电压。普通 pipx 安装需要重装桥接；可编辑安装直接使用修改后的源码。

USB 保护依据：[ESP-IDF 5.5.3 USB 与睡眠](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-guides/usb-serial-jtag-console.html#automatic-and-manual-sleep-entry)。旧说明将 USB 限制用于所有模式，范围过宽。电池 Wi-Fi 可以使用自动浅睡眠，USB 主机连接时单独阻止入睡。

## 续航目标的计算

以下仅按 BSP 的标称 520 mAh 估算，假设可用容量为 520 mAh。没有测得本机容量、整机电池侧平均电流或转换效率。

| 续航目标 | 电池侧允许的平均电流 |
| --- | ---: |
| 24 小时 | 21.7 mA |
| 48 小时 | 10.8 mA |
| 72 小时 | 7.2 mA |
| 7 天 | 3.1 mA |

计算为 `平均电流 = 可用容量 / 时间`。若实际容量较低，同样电流的续航也会降低。99% 到 0% 的显示变化不能直接换算成已消耗 514.8 mAh。

ESP32-C3 数据手册给出的 Modem-sleep 典型电流仍为十几到几十 mA，取决于频率、CPU 状态与外设。其 130 µA Light-sleep 和 5 µA Deep-sleep 是指定条件下的芯片数据，不能用于承诺整机待机时间。无线收发、外置功放、屏幕、电量计、稳压电路和周期唤醒均需计入。[ESP32-C3 数据手册 v2.4，第 56–57 页](https://www.espressif.com/sites/default/files/documentation/esp32-c3_datasheet_en.pdf)。

## 实机排查和验收

先完成充电。使用同一设备、同一固件和同一电池温度比较各状态。USB 连接可能充电，也会阻止本版自动浅睡眠；USB 插着的读数不能代表电池 Wi-Fi 待机。

| 测试 | 操作和记录 | 判断目的 |
| --- | --- | --- |
| 原版是否持续开麦 | 使用结束后检查 `mic=false`、`audio=false`；确认空闲屏幕是否熄灭 | 排除说话少但音频持续采集 |
| 新版冷启动 | 检查 `power_profile=idle-v1`、有效电量/电压、`codec_asleep=true`、无错误；随后开麦和关麦 | 检查首次采集及已知待机状态 |
| 30/60 秒空闲 | 电池 Wi-Fi 关麦后等待；30 秒屏幕休眠，60 秒连接断开，Mac 进入等待 | 检查省电状态是否达到 |
| 按键重连 | 分别用上、下、确认键唤醒；重连后再按确认输入并确认结束 | 检查唤醒键不会误切模式或触发输入 |
| 重复恢复 | 至少重复 10 次空闲、唤醒、输入、结束 | 检查黑屏、音频唤醒失败、旧快捷键重放和默认输入未还原 |
| 弱信号与断网 | 测试 AP 不可达、Mac 睡眠/唤醒和 DHCP 地址变化 | 检查 60 秒停无线及桥接恢复；记录开麦延迟和丢帧 |
| USB | USB 输入、关麦、拔插、配网；退出时检查默认输入还原 | 检查浅睡眠保护没有破坏有线使用 |
| 电池续航 | 从相近 SOC 开始，记录起止时间、SOC、电压和累计录音时长；先观察 4 小时，再观察 24 小时 | 比较实际电量下降。唤醒读数会短暂增加耗电，需记录 |

若可以测量电池侧电流，分别记录：硬件关机、冷启动关麦、开麦后再关麦、亮屏、30 秒屏幕休眠、60 秒停无线、连续录音。状态稳定后取一段时间的平均值，并记录 RF 发射峰值。不要只用单次瞬时读数。

USB 表读的是 USB 输入侧电流，包含充电及转换损耗。它可用于同条件对比，但不能替代拔线后的电池侧测量。先做软件状态和电量对比，无需为了本轮验证先购买仪表。

若新版本在停无线后仍明显掉电，按顺序检查：CPU 是否实际进入浅睡眠及阻止它的电源锁；功放、codec 和稳压电路的静态电流；CW2017 电压与 SOC 的一致性；充满状态与有效容量。硬件关机后仍快速掉电时，软件任务无法解释，应重点查电池、充电及漏电路径。

## 后续方案

本版先采用停无线与自动浅睡眠。它保留 RAM 和现有 ADC 按键识别，不增加新的硬件唤醒路径。实际待机电流达到目标后即可停止扩展。

若浅睡眠仍不能达到目标，再评估 Deep-sleep。该模式会重启应用并重新连接 Wi-Fi，需要处理模式恢复和首个按键。三键共用 GPIO0 的电阻分压；Deep-sleep 的数字唤醒必须实测三键在不同电量下都达到低电平阈值。不能直接套用独立 GPIO 按键示例。还需暂停电量计、音频、共享 I2C 和显示，并正确处理引脚保持。当前语音版本未实现这些行为。

如果残余耗电来自无法控制的功放或电源电路，继续调软件的收益会受限。是否修改硬件应依据测得的电流，而非芯片手册的最低值。

## 2026-10-07 二次优化

用户反馈第一版比前一天明显省电，目前还有约 50%。设备放置十几个小时后，电量仍下降约 30%–40%。用户确认期间没有连接 USB，麦克风关闭，屏幕熄灭。该观察排除了这次隔夜持续开麦和 USB 主机保护，但没有证明 CPU 实际浅睡比例。

用户还反馈，断连后的按键恢复需要数秒，有时约 10 秒。用户否决将空闲阈值延长到 10 分钟，要求继续以设备省电为重点，并加快恢复。实现保留 60 秒空闲阈值，不增加使用模式或设置项。

**代码事实**：`idle-v1` 停 Wi-Fi 后，ADC 按键仍每 20 ms 扫描；音频和传输任务每 100 ms 检查，主循环每 500 ms 醒来。停止 LVGL tick 后，其任务也保留等待超时。Mac 的重试等待逐步增长到 10 秒，另有 3 秒 TCP 建连和自动发现窗口。频繁唤醒存在优化空间；Mac 的等待会延长恢复。没有电流或电源锁记录，不能把 30%–40% 掉电全部归因于这些路径。

**新实现**：使用[空闲电源模块](firmware/main/voice_power.c)，复用固定官方 BSP 的深睡准备接口。模块依赖语音运行层；运行层只报告状态，不反向依赖电源模块。

| 条件或状态 | `idle-v2` 行为 |
| --- | --- |
| 关麦、30 秒无操作 | 保留面板休眠和熄屏 |
| Wi-Fi 模式、关麦、60 秒无操作 | 保留停止无线和关闭网络连接 |
| 已熄屏、codec 已睡眠、运行初始化成功、USB 主机未连接、按键松开 | 请求音频和传输任务在安全位置暂停；最多等待 1.5 秒。无线停止必须成功 |
| 已暂停任务 | 停 ADC 按键定时器，设置 GPIO0 低电平唤醒。使用板上外部上拉；禁用 IDF 自动添加内部上下拉 |
| 唤醒源配置成功 | 按电量计、codec、I2S 引脚、共享 I2C 引脚、显示的顺序关闭外设，进入深睡。无周期唤醒 |
| 外设关闭前的准备失败 | 恢复任务、按键和 ADC 输入状态。若已清除唤醒源，恢复 Wi-Fi 浅睡唤醒源。此次空闲不连续重试 |
| 外设关闭时返回错误 | 记录第一个错误并继续深睡。总线释放后不能在原运行中回滚；唤醒重启后重建 |
| 按上键唤醒并松开 | 解除 GPIO 保持。连续确认松开 80 ms 后才创建 ADC 按键。恢复 Wi-Fi 模式，保持关麦；不执行唤醒键的输入操作 |
| USB 主机已连接，或使用 USB 模式 | 不进入此深睡流程。已深睡时需先按上键，单独插 USB 不由应用唤醒 |
| Mac 断连 | 固定 1 秒重试；重连的 TCP 超时为 1 秒，每两次失败进行一次 1 秒地址发现。正常初次连接仍用 3 秒窗口 |
| 网络尚未连接 | 不反复创建音频设备；认证和传输模式校验后才初始化音频 |

准备阶段持有 `ESP_PM_NO_LIGHT_SLEEP` 锁。它防止 BSP 延时期间的自动浅睡重新添加定时唤醒。深睡只保留 GPIO 唤醒源，避免设备持续定时重启。

GPIO0 为三键共用 ADC 引脚。BSP 定义上键为 0 Ω 接地，因此文档以短按上键作为恢复方法。下键和确认键的分压也可能达到低电平，但需在不同电量下实测，不能承诺三键均可深睡唤醒。关机或普通复位仍回 USB 模式；仅本应用的 GPIO 深睡唤醒恢复 Wi-Fi。模式放在 RTC 内存，不增加 NVS 写入。

状态新增 `power_profile=idle-v2`、`usb_host`、`deep_wakes` 和 `sleep_error`。Mac 会显示这些字段。深睡唤醒后计数增长；普通复位清零。`sleep_error` 保留上次外设关闭的第一个错误。计数可以验证进入过深睡，不能证明电池侧电流。深睡期间没有网络状态采样。

设计依据：ESP32-C3 深睡关闭 CPU、主要 RAM 与数字外设；GPIO0 属于可深睡唤醒的 RTC 供电引脚。退出后重新启动应用。[ESP-IDF 5.5.3 睡眠与 GPIO 唤醒](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/system/sleep_modes.html)。USB 主机连接检测基于 SOF；无需打开串口即可阻止深睡，驱动实现为 `esp_driver_usb_serial_jtag/src/usb_serial_jtag_connection_monitor.c`。

这次减少的是长时间待机的软件运行和周期唤醒。外置功放仍不可由 MCU 断电。电源电路、codec、面板和电池的残余耗电仍需测量。CW2017 从休眠恢复后会重新计算 SOC；对比掉电时同时记录电压，不能只看唤醒瞬间的百分比。

**待做实机验收**：在连接设备的 Mac 更新桥接并刷入应用。先做短周期恢复，再做隔夜比较。

1. 冷启动确认 `idle-v2`、`mic=false`、`codec_asleep=true`、有效电量和电压。拔掉 USB，选择 Wi-Fi 并输入一次。
2. 关麦后记录起始时间、SOC 和电压。30 秒后熄屏，60 秒后断连。等两分钟，短按上键并松开。
3. 确认恢复 Wi-Fi，`deep_wakes` 增长、`sleep_error=0`。记录按下上键到桥接 ready 的时间，再按确认输入并结束。
4. 重复至少 10 次。测试按住上键再松开，确认不会自动开麦；再测试另外两键在高、低电量下能否唤醒。
5. 测试 USB 连接时不深睡、深睡后按键再接 USB、USB 配网及输入。USB 打开导致的普通复位仍按原规则返回 USB。
6. 从相近 SOC 开始，拔线、关麦、熄屏放置与第一版相近的十几个小时。记录起止时间、SOC、电压、累计输入时间和深睡唤醒计数。SOC 稳定后再比较。

1 秒仅是 Mac 重试间隔。总恢复时间还包含按键释放、应用启动、电量计恢复、Wi-Fi 关联、DHCP、认证及音频初始化。尚无实体设备测量，不能承诺 1 秒可输入，也不能承诺具体待机天数。
