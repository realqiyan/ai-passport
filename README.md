# AI Passport：语音输入

更新日期：2026-10-06。

目标：使用设备自带麦克风，通过 USB 或 Wi-Fi 向 Mac 语音输入法传送音频，并用设备按键触发输入。

入口：[语音应用与安装说明](voice/README.md)、[耗电排查](voice/POWER.md)、[开发手册](DEVELOPMENT.md)、[稳定性与迁移审查](voice/REVIEW.md)、[方案分析](VOICE-INPUT.md)。

## 当前状态

设备独立语音应用和 Mac 桥接已实现。音频通过 BlackHole 2ch 和聚合设备 `Passport Mic` 送入输入法；快捷键由 Mac 注入。此前在 Apple Silicon Mac 上实测 USB 与 Wi-Fi 出字，拔掉 USB 后电池供电的 Wi-Fi 输入也通过。

当前代码支持确认键临时输入：关麦时确认开始，再次确认结束并关麦。上键保留持续开麦。快捷键可保存到设备或在启动时覆盖。

2026-10-06 用户反馈 Wi-Fi 与 Mac 桥接保持连接，少量说话仍在一天内耗尽电量。按用户确认的续航优先取舍，已实现关麦空闲 60 秒停 Wi-Fi、自动浅睡眠、30 秒屏幕控制器休眠，以及 Mac 自动重连。首次按键只用于唤醒，重连 ready 后再次确认输入。完整门禁通过；桥接 102 项中 100 项通过、2 项跳过，脚本测试 26 项通过。应用镜像 1,216,640 字节，归档 `4fd22b78…` 校验通过；新版未刷入设备，实际功耗未测。代码证据与验收计划见[耗电排查](voice/POWER.md)。

Wi-Fi 启动支持局域网自动发现：更新固件和 Mac 桥接后，设备切到 Wi-Fi 模式即可运行 `passport-voice wifi`（或 `start.sh wifi`），无需先输入 IP。发现超时后尝试上次地址；找到多台时需指定 IP。操作与兼容条件见[Wi-Fi 使用](voice/README.md#wi-fi-使用)。

Mac 侧的启动入口为 `passport-voice usb|wifi`，可用 pipx 装到 `~/.local/bin`；`start.sh` 是转发参数的薄包装。环境由 pipx 管理，`setup` 和 `cleanup` 负责音频设备及用户状态。安装与用法见[语音应用说明](voice/README.md#pipx-安装与更新)。

pipx 迁移修复已完成。Linux 桥接固定数据测试 95 项中 93 项通过、2 项跳过；脚本与刷机测试 26 项通过。隔离环境的普通安装、可编辑安装和命令入口已验证。Mac 音频及完整语音输入仍待实机验收。

此前含自动发现版本的完整固件门禁通过，应用镜像 1,213,136 字节。当时 macOS 桥接测试 70 项、脚本与刷机固定数据测试 26 项全部通过（Linux 上另有 2 项因缺 macOS 框架跳过）。该固件已于 2026-10-06 刷入设备，尚不包含本轮停无线省电改动；固件归档身份和验收边界见[审查记录](voice/REVIEW.md)。

## 源码与构建目录

| 路径 | 用途 |
| --- | --- |
| `voice/firmware/` | 维护的应用源码与 C 测试 |
| `voice/bridge/` | Mac 音频桥接与 Python 测试 |
| `apply_voice.py` | 将应用源码应用到固定官方基线 |
| `source/` | 官方基线仓库，承载共享 Git 数据和完整驱动、组件、构建工程 |
| `voice-source/` | 语音应用构建工作树及固件归档 |
| `.tools/`、`env.sh` | ESP-IDF 工具链与环境入口 |

当前编译依赖完整官方工程。先运行 `apply_voice.py`，再在 `voice-source/` 构建。`source/` 保持官方基线，工作树关系和语音归档已核验。

`source/` 和 `voice-source/` 均在 `.gitignore` 中。根仓库的 commit/push 不包含它们，`git clone`、`git pull` 和 `git restore` 也不会恢复它们。此前恢复仅发生在当时的本机工作区，不代表其他机器已有这些目录。

首次检出、换机器或目录缺失时，按[开发手册的恢复步骤](DEVELOPMENT.md#恢复固件源码)下载固定官方基线、创建语音工作树，再运行 `apply_voice.py`。ESP-IDF 工具链需另行安装；维护源码和文档由根仓库保存。

## 打开 USB 串口会复位设备

ESP32-C3 的 USB Serial/JTAG 在主机打开串口时可能复位设备。本设备实测出现 `rst:0x15 (USB_UART_CHIP_RESET)`；这与崩溃复位不同。

- USB 桥接每次启动可能复位设备一次。反复打开串口会造成连续重启的表象。
- 复位后传输模式回到 USB。Wi-Fi 输入期间用串口查状态，会中断会话；改用设备屏幕或网络通道。
- `flash.sh --list-ports` 只枚举串口，不打开设备。
